## Why

The product name is going back from **Guestify** to **Visimio**. The backend
(`VMSS_API`) rename is finished but not yet deployed: emails, the From name,
the footer and the OpenAPI title already say Visimio, and the email logo
moved to `/api/v1/public/email-assets/visimio-logo.png`. The web portal
must match, so users don't see mixed names once the backend ships. Ideally
web, mobile and backend deploy together.

The API contract is unchanged (no endpoints, fields or response shapes), so
the data layer is untouched.

## What Changes

- **Brand source.** `src/presentation/brand.ts`: `BRAND_NAME = 'Visimio'`;
  the three logo imports point at `logo-visimio*.svg`.
- **Assets.** Replace the `logo-guestify*.svg` files with generated
  `logo-visimio*.png` (1x and @2x), restoring `srcSet` in `BrandLogo`; remove
  `public/favicon.svg`; replace
  `favicon.png`, `favicon-32.png` and `apple-touch-icon.png`. All are
  generated by the backend script
  `VMSS_API/scripts/build_brand_assets.py --web-out <path>`; regenerate
  rather than hand-edit.
- **Literals.** `index.html` `<title>`, the fallback notification title in
  `public/firebase-messaging-sw.js`, and the e2e files that reference the
  Guestify name/logo (`e2e/test_toasts.py`, `e2e/test_theme_mode.py`).
- **Brand guard.** `scripts/check-brand.mjs` currently fails on "Visimio";
  flip it to reject `VisitorPass|Guestify` (case-insensitive) so lint
  passes and the old name can't creep back.
- **Specs.** Update `brand-identity`, `staff-login` and `staff-sso-login`
  to the Visimio wording.
- **Supersedes** the unarchived `rebrand-to-guestify` change (drop it) and
  retarget the Guestify wording in the in-flight `modernize-visitor-flow-pages`
  and `modernize-visitor-landing-page` changes.
- **Sweep.** `grep -rniE guestify` across src, public, index.html, e2e,
  config, `.env*`, docs and openspec must come back clean (archived changes
  excepted, as history).
- **Mobile app** is a separate repo, not in this workspace. It needs the same
  rename (UI copy, app/store names, deep-link/share text, client-built
  email/SMS copy, logos and icons). It is tracked as a coordination item,
  not implemented here.

## Capabilities

### New Capabilities
None.

### Modified Capabilities
- `brand-identity`: product name, logo/mark, favicon, title, copyright line and
  accessible names become Visimio; the retired-name set becomes
  "VisitorPass" and "Guestify".
- `staff-login`: the brand panel shows the Visimio on-dark logo.
- `staff-sso-login`: the brand panel shows the Visimio on-dark logo.

## Impact

- Code: `brand.ts`, `index.html`, `public/*`, `scripts/check-brand.mjs`,
  `src/assets/brand/*`, two e2e files. Components already read from
  `brand.ts`, so no component edits are expected.
- Dependencies: the backend logo script (needs the Visimio master).
  Build output `dist/` is regenerated, not edited.
- No API, data-layer or schema changes.
- Release: should ship with the backend and mobile releases.
