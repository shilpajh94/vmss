## Why

The product is being renamed from **Visimio** to **Guestify**, with a new
logo (the supplied raster is `assets/guestify-logo-source.png`). The logo has a teal location-pin
"G" mark, and a wordmark with "Gu" in teal and "estify" in white, on a navy
background. Every email the API sends still carries the Visimio logo, the
"Visimio" From name and "Powered by / © Visimio" footer. A logo saying one
name next to copy saying another would look broken. The portal is being
rebranded in parallel by the paired `VMMS_WEB` change of the same name
(`rebrand-to-guestify`). The portal's PNGs are generated by this repo's
`scripts/build_brand_assets.py`, so this change ships first.

## What Changes

- **A high-quality vector logo master, built before anything else.** The
  supplied image is a flattened raster with soft edges and compression
  noise. Keying it directly would carry that noise into every logo. So it
  is rebuilt as SVG, in `brand/` at the repo root:
  - `guestify-mark.svg`: the teal "G" pin, with its outline traced into
    clean vector paths, and its soft ribbon shading kept as a denoised
    image layer clipped by that outline;
  - `guestify-lockup-on-dark.svg`: the mark plus the "Guestify" wordmark,
    set in the closest-matching open-licence bold geometric font and
    converted to outlines ("Gu" teal, "estify" white);
  - `guestify-lockup-light.svg`: the same, with "estify" in navy `#12172A`.

  The SVGs have transparent backgrounds and no font dependency. You
  review them side by side with the original before the rest of the
  change is applied. The original raster stays only as the tracing
  reference (`assets/guestify-logo-source.png` in this change).
- **`scripts/build_brand_assets.py` renders from the SVG master:**
  - it rasterises each SVG at the exact pixel size needed, with no
    keying, recolouring or downscaling of a noisy source;
  - it writes the email logo (`guestify-logo-on-dark.png`) and, with
    `--web-out`, the portal's logo SVGs, favicons and touch icon.
  - The old Visimio raster pipeline (`_on_dark` recolour, transparent-PNG
    source) is removed.
- **Email branding switches to Guestify:**
  - header logo image and its alt text "Guestify";
  - the text-wordmark fallback (no asset base URL configured) reads
    "Gu**estify**" in the logo's two colours;
  - footer "Sent by {company or Guestify}", "Powered by Guestify",
    "© {year} Guestify. All rights reserved." in both HTML and plain text.
- **Logo URL renamed** to `GET /api/v1/public/email-assets/guestify-logo.png`.
  The URL is cached as `immutable`, so the file needs a new name. The old
  `visimio-logo.png` path stays as an alias serving the new image, so emails
  already sitting in inboxes never show a broken image.
- **Settings defaults:** `app_name` becomes "Guestify API" and
  `SMTP_FROM_NAME` becomes "Guestify". `.env.example` comments are updated.
  The local `.env` is not edited by this change.
- Docs (`docs/features/notifications.md`, `invitations.md`,
  `identity_verification.md`, `reports.md`, `sso_authentication.md`), the
  OpenAPI tag text in `main.py`, code comments, docstrings and tests drop
  "Visimio" in favour of "Guestify".

Out of scope:
- internal identifiers: the `vmss_api` package, `VMSS_*`-style env var
  names, repo names, Redis key prefix `vmss:`, the `vmss` CID domain
  suffix;
- tenant-uploaded company logos, which still replace the product logo in
  the email header;
- SMS/WhatsApp copy in code: there is none. Every message is a
  DLT-registered Fast2SMS template whose text and sender ID live in the
  provider's portal, not in this repo. Whether they name Visimio can't be
  checked from code, so it's a manual verification task (9.4). Changing
  one means re-registering it with DLT, which has an approval lead time;
- the email colour palette (teal accent, navy header). The new logo's teal
  and navy are close enough that no palette change is needed.

## Impact

- New `brand/` directory holding the three master SVGs, plus the OFL
  licence text of the wordmark font. Its glyphs are embedded as outlines,
  and OFL requires the licence to travel with the outlines.
- New or replaced assets: `src/vmss_api/core/email_assets/guestify-logo-on-dark.png`,
  rendered from the master. The two `visimio-*` PNGs are removed, and no
  raster source is kept under `src/`.
- New **dev-only** dependencies, used by the one-off build tooling and
  never imported at runtime:
  - `vtracer` (raster → SVG tracing of the mark);
  - `fonttools` (font glyphs → SVG outlines);
  - `resvg-py` (SVG → PNG rendering).
- Code: `scripts/build_brand_assets.py`, `core/email_assets.py`,
  `core/email_assets_router.py`, `core/emailing.py` (logo path, CID name),
  `core/email_templates/base.html` / `base.txt`, `core/config.py`, `main.py`.
- Tests: `tests/test_email_notifications.py`, `tests/test_email_assets.py`,
  the Mailpit assertions in `invitations/tests.py`, and
  `identity_verification/tests.py`.
- `scripts/qa_regression/run.py` and `scripts/send_email_previews.py` use the
  new logo path and preview address.
- No migration, no new runtime dependency, no breaking API change: the
  old logo URL keeps working.
- Ops: a deployment that sets `SMTP_FROM_NAME=Visimio` explicitly in its
  `.env` keeps sending as "Visimio" until that value is changed. This is
  called out in the migration plan.
